## ROS2 复核边界

本次同时改进并重跑了 Windows 演示脚本：日志现在写入本次 artifact 目录，单行日志统计不会报错，并可在 CycloneDDS 与 Fast DDS 之间切换。

但在当前受限 Windows 会话中，两种 DDS 都没有建立发布器与订阅节点之间的发现：发布器日志显示已读取并发送 20 帧，`ros2 topic list` 只有 `/parameter_events` 和 `/rosout`，里程计指标仍为 0 行，最终按 60 秒超时退出。因此本次不能把 ROS2 重新运行写成成功，也不能仅凭节点启动就证明数据链路有效。

仓库中的 RViz 截图与 796 帧 ROS2 记录是早期实际运行留下的历史证据，README 已明确它使用旧的时间戳协议。后续应在干净 Ubuntu/ROS2 环境完成 790 帧一对一协议回放，再替换这部分历史结果。

## 当前最适合展示的内容

1. **公平基线**：静止、NumPy point-to-point 与 Open3D point-to-plane 使用相同的 790 帧、内参、失败门限和 ATE/RPE 实现。
2. **真实效果**：fr1/xyz 上 Open3D ATE 为 `0.058947 m`，明显优于静止基线 `0.186227 m`；同时保留 desk/desk2 的漂移结果。
3. **跨语言核对**：Python 与 C++ 在同协议下的 ATE 相差约 `0.075 mm`。
4. **回环风险实验**：正常位姿图将关键帧 ATE 从 `0.044338 m` 降至 `0.029692 m`；强制错误边后恶化至 `0.464398 m`。
5. **诚实的学习实验**：冻结 ImageNet 特征优于当前微调模型，因此没有把 MobileNetV3+SE 包装成已有增益。
6. **可视化证据**：README 可直接查看真实点云、优化前后轨迹、正确/错误回环和历史 ROS2 RViz 截图。
