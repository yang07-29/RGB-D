# RGB-D 项目改进清单

审阅日期：2026-09-14。仓库：<https://github.com/yang07-29/RGB-D>。

这份清单同时记录改进状态。优先级按对结果可信度、复现和系统能力的影响排列；每项只有在代码、测试和真实运行证据齐全后才标为完成。

当前进度（2026-09-14）：P0 的 01–04 与 P1 的 05–07 已完成。下一项是 08 位姿图边质量和错误回环。

## P0：先修正评测和验证问题

### 01. 统一配准质量指标与失败门限

状态：**已完成**。共享最终变换质量函数已接入 NumPy/Open3D；18 组实验已在 `results/parameter_sweep_one_to_one_quality_v2/` 重跑。

- 现状：NumPy ICP 对全部源点统计最近邻 RMSE；Open3D 使用阈值内点的 `inlier_rmse`。参数实验却使用同一个数值门限。Open3D 的 RMSE 门限等于对应点距离门限时，高 RMSE 拒绝条件基本不起作用。
- 影响：拒绝帧数存在口径差异；完整里程计轨迹也受不同接受策略影响。
- 改进：在最终变换后，用共享评估函数重新计算对应点比例、内点 RMSE、全点 RMSE；明确各指标用途，分开对应距离与质量门限。
- 验收：相同点云和变换在各后端得到一致的质量指标；冻结新协议后重跑 18 组实验，以新目录保存，保留旧结果及协议版本。
- 依据：[geometry.py](../src/geometry.py)、[open3d_odometry.py](../src/open3d_odometry.py)、[参数实验脚本](../scripts/run_parameter_sweep.ps1)。

### 02. 拒绝无效数值和无效变换

状态：**已完成**。NaN/Inf、空点云、非刚体旋转、非法齐次矩阵和非法阈值已有回归测试。

- 现状：`registration_failure_reason` 只做大小比较。审阅时传入 NaN，函数返回 `None`，即接受。
- 影响：异常结果可能绕过门限；这不说明现有轨迹已经出现 NaN。
- 改进：检查指标、点云和位姿是否有限；验证旋转正交性、行列式和位姿形状；非法参数明确报错。
- 验收：NaN、Inf、空点云、退化输入、非法旋转等针对性测试通过；错误状态不会更新有效位姿。
- 依据：[quality.py](../src/quality.py)、[geometry.py](../src/geometry.py)。

## P1：补足实验说服力和运行稳定性

### 05. 固定参数后开展多序列评测

状态：**已完成三序列版本**。固定 `voxel=0.05 m`、`correspondence=0.08 m` 后运行 fr1/xyz、fr1/desk、fr1/desk2，九行统一结果见 `results/multi_sequence_one_to_one_quality_v2/`。

- 现状：主要里程计和位姿图结果集中在 fr1/xyz 的 796 帧、约 26.6 秒；最好参数来自同序列网格搜索。
- 改进：把调参序列与最终评测序列分开；覆盖不同运动、几何和遮挡条件；加入一个成熟 RGB-D 方法作参照。
- 验收：建议至少 3–5 条评测序列，使用冻结配置；报告每条结果、失败情况和汇总，而不是只展示最佳序列。

### 06. 独立复核轨迹指标与时间戳协议

状态：**已完成**。RGB-D 加载与真值附加已经拆分；NumPy/Open3D 在没有 groundtruth 时仍输出轨迹。evo 1.37.1 对 790 帧 ATE、Δ=1/30 RPE 的最大绝对差为 `1.065e-09`，低于 `1e-8` 容差，原始结果见 `results/evo_crosscheck_one_to_one_v2/`。

- 现状：ATE/RPE 有自实现和基础测试，尚缺独立工具的对照记录；真值采用最近邻关联。
- 改进：用独立评测实现核对 SE(3) ATE 和相同配对规则的 RPE；增加较长时间间隔 RPE；检查排序、重复关联和轨迹长度不一致。将 RGB-D 读取与真值关联分离，以支持无真值输入。
- 验收：同一保存轨迹在两套评测实现中的差异有明确容差；时间戳策略、尺度、配对数均记录；无 groundtruth 文件时仍可生成轨迹。
- 依据：[metrics.py](../src/metrics.py)、[tum.py](../src/tum.py)。

### 07. 补跟踪丢失检测与恢复

状态：**已完成实验版**。定义连续 2 帧拒绝为 LOST，加入单位/恒速候选、粗到细重试、最近有效关键帧和内部暂定位姿链。step=1/2/3 六组压力实验记录丢失、恢复率、恢复帧数、ATE/RPE 和延迟；策略在 step=3 降低 ATE，但在 step=2 与短间隔 RPE 上存在退化，因此保留为可选模式，不替换默认基线。

- 现状：逐帧 ICP 采用单位初值，拒绝后保持上一位姿并继续；没有完整的丢失/恢复状态流程。
- 改进：比较运动预测与多尺度 ICP；增加连续失败状态、关键帧重定位和恢复策略。
- 验收：人为跳帧、快速运动、低重叠测试中记录丢失次数、恢复成功率、恢复时间和轨迹误差。
- 依据：[run_odometry.py](../src/run_odometry.py)、[ROS2 C++ 节点](../ros2_ws/src/rgbd_odometry_ros/src/rgbd_odometry_node.cpp)。

### 08. 检查位姿图边质量和错误回环

- 现状：相邻关键帧 ICP 边直接标记 `uncertain=False`，没有先经过接受门限；正式回环之外仅有两个错误候选压力案例。
- 改进：检查顺序边的有效对应、残差和退化情况；扩大错误回环测试；验证错误边对优化的影响。
- 验收：坏顺序边和错误回环有明确处理；在相同关键帧上比较优化前后 ATE/RPE，并统计误接受和误拒绝。
- 依据：[pose_graph_slam.py](../src/pose_graph_slam.py)、[回环结果](../results/pose_graph/README.md)。

### 09. 统一性能统计范围并做长序列测试

- 现状：离线 Python 提前缓存全序列点云，RSS 受序列长度影响；ROS2 C++ 计时在 CSV/RSS 写入前结束，结果文档却将这些记录包含在计时范围内。
- 改进：给各计时区间明确起止点；区分计算吞吐与输入到输出延迟；逐帧流式处理；记录预热、重复运行和内存采样方式。
- 验收：同硬件、同参数下分别报告计算和端到端耗时；至少重复 3 次；长时间回放时延迟和内存曲线可检查。
- 依据：[run_odometry.py](../src/run_odometry.py)、[open3d_odometry.py](../src/open3d_odometry.py)、[ROS2 C++ 节点](../ros2_ws/src/rgbd_odometry_ros/src/rgbd_odometry_node.cpp)、[ROS2 C++ 结果说明](../results/ros2_cpp_linux_full/README.md)。

### 10. 补充学习特征的增益与消融证据

- 现状：有/无 SE 的 Recall@1/5 相同；学习回环的最终 ATE 未优于传统回环。无 SE 版本是从带 SE 的预训练网络删除模块得到，初始化条件需要单独解释。
- 改进：加入未经微调的预训练特征基线、多随机种子、困难负例和更清晰的 SE 消融；统一延迟比较范围。
- 验收：报告均值和波动、Recall/P/R/F1，以及接入回环后的 ATE；以实验判断模型在哪些情形值得使用。
- 依据：[模型代码](../src/loop_learning.py)、[训练代码](../src/train_loop_descriptor.py)、[学习结果](../results/loop_learning/README.md)。

## P2：把分开的模块组成可持续运行的系统

### 11. 接通 ROS2 在线关键帧、回环与后端优化

- 现状：ROS2 节点运行逐帧 ICP，回环和位姿图是独立离线流程。
- 改进：建立关键帧队列、后台回环与优化、map/odom 关系和优化结果更新机制。
- 验收：在一次持续回放中展示回环检测、轨迹修正与地图更新，记录后台处理对前端延迟的影响。

### 12. 完善 ROS2 输入适配与长时间运行

- 现状：C++ 节点将深度尺度写死为 5000，使用 16UC1；`/path` 无限追加并每帧整体发布；Odometry 主要填位姿。
- 改进：参数化深度单位，支持需要的深度编码和标定；检查输入时间戳、帧名与 CameraInfo；限制轨迹历史或降频发布；明确速度与协方差语义。
- 验收：至少覆盖两种深度输入配置；输入缺失/不同步时行为明确；长时间回放的内存、消息大小、丢帧和延迟可控。
- 依据：[ROS2 C++ 节点](../ros2_ws/src/rgbd_odometry_ros/src/rgbd_odometry_node.cpp)。

### 13. 增加地图融合与地图质量评估

- 现状：地图由变换后的关键帧点云合并、体素下采样得到。
- 改进：先量化重影、噪声和覆盖率；依据应用需要选择 surfel 或 TSDF 融合，并支持优化后的地图更新。
- 验收：同一数据、相同视角展示融合前后，并提供可计算的质量指标；有网格导出需求时再加入网格。
- 依据：[pose_graph_slam.py](../src/pose_graph_slam.py)。

### 14. 增强 C++ 的可维护性与回归验证

- 现状：核心 C++ 有一个 CTest 可执行程序，内部五组基础检查；异常输入和长序列回归覆盖有限。
- 改进：增加边界测试、跨语言输出对照、编译警告检查及 sanitizer；统一参数配置和错误处理，逐步减少重复实现。
- 验收：同协议下 Python/C++ 输出差异有容差；新增功能不会引入相关警告、内存错误或历史轨迹回归。
- 依据：[C++ 测试](../cpp/tests/test_core.cpp)、[CMake](../cpp/CMakeLists.txt)。
